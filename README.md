# 🎮 Rock Paper Scissors Game

A sleek, modern, and fully responsive web application of the classic "Rock, Paper, Scissors" game. This project is built using core front-end web technologies, focusing heavily on clean UI/UX and fluid layout adaptivity across various devices.

🚀 **[Live Demo Link](https://rock-paper-scissors-game-beige-alpha.vercel.app/)**

---

## ✨ Features

- **Modern UI (Dark Mode):** Features an eye-friendly, high-contrast palette utilizing a dark theme with vibrant glow and interactive hover effects.
- **Fully Responsive Design:** Engineered completely from scratch using **CSS Flexbox** and strategic **Media Queries**. The layout flows dynamically and adjusts beautifully across mobile phones, tablets, and desktop screens without breaking or overlapping.
- **Data Persistence:** Integrates HTML5 **LocalStorage** API to securely save and display the user and computer score history, preventing data loss when refreshing or closing the browser session.
- **Dynamic DOM Updates:** Seamless execution of game states, asynchronous loading animations, and automated resetting behavior managed natively through JavaScript.

---

## 🛠️ Technologies Used

- **HTML5:** Structured semantic markup defining the application's layout components.
- **CSS3:** Powers the styling, modern color theory foundations, component-specific typography, Flexbox alignments, and interactive pseudo-classes (`:hover`).
- **JavaScript (ES6+):** Controls the overall game logic, array-based randomized choices for the opponent, scoring structures, and conditional flow execution.
- **Font Awesome v7:** Supplies high-resolution vector scalable iconography for all selectable game elements.

---

## 📈 Refactoring & Optimization Journey

This project highlights a significant milestone in transitioning from traditional element alignments to scalable modern design practices:

1.  **Phase 1 (Legacy Build):** Relied on rigid absolute positions and rigid negative margins. This caused layout fragility and broken components when tested on variable viewports.
2.  **Phase 2 (Flexbox Migration):** Stripped out hardcoded constraints in favor of a fluid fluid-grid framework. Handled component arrangement responsively using `justify-content` and flexible percentages.
3.  **Phase 3 (Logic Stabilization):** Optimized conditional JS pathways. Fixed rendering loops by modifying inline element `display` values from breaking block formats over to layout-compliant Flex structures.
